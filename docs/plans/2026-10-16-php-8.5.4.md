# PHP 8.5.4

## Context
Issue #26. The repo targeted PHP 8.1: `composer.json` and both PR jobs' `setup-php` said 8.1, while the daily run used the runner's preinstalled PHP, 8.3.6 on `ubuntu-latest` (Ubuntu 24.04). CI tested one version and production ran another. The repo had no mise config, so local PHP came from each developer's global mise config.

`ubuntu-latest` moves to Ubuntu 26.04, which ships PHP 8.5.4, between 2026-10-19 and 2026-11-19 (actions/runner-images#14748). The repo follows it and targets 8.5.4.

## Change
`composer.json` sets `require.php` to `^8.5.4` and `config.platform.php` to `8.5.4`. `composer.lock` is refreshed through composer for the new platform. One package had to move: `codeception/codeception` 5.2.2 refuses to run on PHP 8.5, whose CLI reports `register_argc_argv` as off, so it is raised to `^5.3.7` (fixed upstream in Codeception#6921). Only that package moves in `composer.lock`; its dependencies stay where they were.

Every job in `.github/workflows/pull-request.yml` and `.github/workflows/daily.yml` runs on `ubuntu-26.04`, so the change can merge before the `ubuntu-latest` migration ends. Both PR jobs set `setup-php` to `'8.5'`. The daily job keeps the runner's preinstalled PHP.

`mise.toml` at the repo root pins `php = "8.5.4"`, and `AGENTS.md` tells agents to stop and ask when `php -v` differs. `.gitignore` lists `mise.lock`, which mise writes when the global `lockfile` setting is on; it records each developer's own PHP backend. mise can't read the version from `composer.json` or `.php-version`: neither PHP plugin supports idiomatic version files.

The `bump-composer` skill and the plans for the GitHub Actions schedule and style checking say 8.5 instead of 8.1.

## Manual steps
1. Run `mise trust` and `mise install` in the repo, as `README.md` describes under "Install".
2. After the `ubuntu-latest` migration ends, switch the workflows back to `ubuntu-latest` in a separate change.

## Verification
- On PHP 8.5.4, `composer install`, `lint:php`, `lint:json`, `lint:style` and `test` pass. `ec` 1.8.1 printed PHP 8.4 nullable-parameter deprecations but still passed; `ec` 2.2.1 prints none.
- `mise current php` in the repo reports `8.5.4`.
- PR CI passes on the pull request, and the next daily run passes.
